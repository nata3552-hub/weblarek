# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает корневой DOM-элемент компонента, который используется для управления его содержимым.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.



## Слой коммуникации

Для взаимодействия приложения с сервером используется отдельный коммуникационный слой — класс `WebLarekApi`.

Класс `WebLarekApi` использует композицию с базовым классом `Api`. В конструктор передается объект, реализующий интерфейс `IApi`. Благодаря этому класс отвечает только за работу с конкретными эндпоинтами API, используя готовые методы базового класса.

### Класс `WebLarekApi`

Класс предназначен для получения данных с сервера и отправки данных о заказе.

#### Конструктор

`constructor(api: IApi)` — принимает экземпляр класса, реализующего интерфейс `IApi`, для выполнения HTTP-запросов.

#### Методы

- `getProducts(): Promise<IProductsResponse>` — выполняет GET-запрос на эндпоинт `/product` с помощью метода `get` класса `Api`. Возвращает объект с количеством товаров и массивом товаров каталога.

- `postOrder(data: IOrder): Promise<IOrderResult>` — выполняет POST-запрос на эндпоинт `/order` с помощью метода `post` класса `Api`. Передает данные покупателя и выбранных товаров и возвращает результат оформления заказа.

Схема взаимодействия:

WebLarekApi
|
| использует
↓
Api
|
| HTTP-запросы
↓
Сервер Web-Larek

Полученные с сервера товары сохраняются в модели `CatalogModel`, которая отвечает за хранение данных каталога внутри приложения.

## Данные

### Интерфейс `IProduct`

```ts
export interface IProduct {
    id: string;
    description: string;
    image: string;
    title: string;
    category: string;
    price: number | null;
}
```

Интерфейс описывает структуру объекта товара, получаемого от сервера и используемого в каталоге, корзине и при оформлении заказа.

### Тип `TPayment`

```ts
export type TPayment = 'card' | 'cash';
```

Определяет возможные способы оплаты заказа.

### Интерфейс `IBuyer`

```ts
export interface IBuyer {
    payment: TPayment | null;
    email: string;
    phone: string;
    address: string;
}
```

Интерфейс описывает данные покупателя, необходимые для оформления заказа.

### Интерфейс `IProductsResponse`

```ts
export interface IProductsResponse {
    total: number;
    items: IProduct[];
}
```

Интерфейс описывает ответ сервера при получении списка товаров. Содержит общее количество товаров и массив объектов `IProduct`.

### Интерфейс `IOrder`

```ts
export interface IOrder extends IBuyer {
    total: number;
    items: string[];
}
```

Интерфейс описывает данные заказа, отправляемые на сервер. Наследует данные покупателя из `IBuyer` и дополнительно содержит общую стоимость заказа и массив идентификаторов выбранных товаров.

### Интерфейс `IOrderResult`

```ts
export interface IOrderResult {
    id: string;
    total: number;
}
```

Интерфейс описывает ответ сервера после успешного оформления заказа. Содержит идентификатор заказа и итоговую сумму покупки.

### Тип `TValidationErrors`

```ts
export type TValidationErrors =
    Partial<Record<keyof IBuyer, string>>;
```

Используется для хранения ошибок валидации данных покупателя. Ключом является название поля, а значением — текст ошибки.

## Presenter

Роль Presenter выполняет файл `src/main.ts`.

Он связывает модели данных и компоненты представления:

- получает данные через `WebLarekApi`;
- передает товары в `CatalogModel`;
- обрабатывает события интерфейса;
- обновляет View при изменении моделей;
- выполняет отправку заказа на сервер;
- управляет переходами между этапами оформления заказа.

# События приложения

## catalog:changed

Генерируется моделью `CatalogModel` после загрузки списка товаров.

## preview:changed

Генерируется при выборе товара для просмотра.

Передает объект `IProduct`.

Используется для открытия модального окна с подробной информацией о товаре.


## basket:changed

Генерируется моделью `BasketModel` при:

- добавлении товара;
- удалении товара;
- очистке корзины.

Используется для обновления:

- счетчика товаров;
- списка корзины;
- общей стоимости.


## buyer:changed

Генерируется моделью `BuyerModel` при изменении данных покупателя.

Используется для:

- проверки валидности формы;
- отображения ошибок;
- блокировки кнопок отправки.

## Поток оформления заказа

Процесс оформления заказа состоит из нескольких этапов:

1. Пользователь выбирает товар в каталоге.
2. При открытии карточки товара вызывается событие `preview:changed`, после чего открывается модальное окно с подробной информацией.
3. Пользователь добавляет товар в корзину. Модель `BasketModel` изменяет список товаров и вызывает событие `basket:changed`.
4. После открытия корзины пользователь переходит к оформлению заказа.
5. В форме заказа пользователь выбирает способ оплаты и вводит адрес доставки.
6. Изменения данных покупателя сохраняются в `BuyerModel` через событие `buyer:changed`.
7. После успешной проверки первой формы открывается форма контактных данных.
8. После заполнения email и телефона данные заказа отправляются через `WebLarekApi.postOrder()`.
9. После успешного ответа сервера отображается окно `Success`, корзина очищается, а данные покупателя сбрасываются.
